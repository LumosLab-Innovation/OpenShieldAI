# Independent next-wave efficacy challenge

Review date: **2026-10-24**. The reviewer owns only this challenge and [independent counterexample tests](../../tests/test_next_wave_adversarial.py). Implementation authors own the controls and evaluator. This is an S1 engineering review, not acceptance of a production identity, egress or publication adapter.

## Claims challenged

| Claim | Required falsifier or useful positive control | Review boundary |
|---|---|---|
| Object authorization stops disclosure | An unsafe cross-object read returns a planted object-specific value; protected forbidden read returns no such value; authorized own-object read still returns its expected value | A read counter with a generic response cannot prove data disclosure was prevented |
| Revocation stops the declared session | Every declared verifier rejects the revoked session, including a request paused before its final authority check; a different user's valid session remains useful | A dispatched operation or bytes already delivered cannot be recalled; no process-restart claim from ephemeral state |
| Idempotency stops duplicate business effects | Concurrent independently approved requests with the same operation key create one independently counted ledger row; a changed operation with the same key conflicts; a fresh approved key remains usable | A receipt or unique HTTP response count is not the business ledger; per-process memory does not supply durability |
| An outbound broker stops a pivot | Actual fixed synthetic allowed receiver receives the legitimate payload; rejected recipient and a redirect produce zero requests at the forbidden receiver; unsafe control delivers there | Fixed loopback receivers do not establish protection for arbitrary DNS, alternate processes or protocols |
| Publication prevents selected new exposure | Clean reviewed snapshot becomes active and functional; changed/unreviewed snapshot cannot become active; old gzip/maps still served are separately observed and retired through exact authority | Promotion denial is not CDN purge, service-worker invalidation or recall of an earlier download |
| AI improves investigation | Real permitted CLIProxyAPI inference, same minimized input and read/action authority as baseline, preregistered cases and per-case accounting for abstention, degradation, useful work and harmful proposals | A transport test double, successful HTTP request, better prose or the same deterministic effect control cannot establish AI advantage |

## Findings requiring implementation changes

1. **Absolute provider deadline bypass, reproduced and fixed.** The gateway originally used a socket inactivity timeout during response-header parsing. A local provider sending a byte every 25 ms completed header parsing after **1.016 seconds** despite a **0.15-second** absolute deadline. The independent regression requires return within 0.65 seconds. The implementation now interrupts the socket at the absolute deadline; the same real-HTTP regression passes. Per-byte activity cannot renew the episode budget.
2. **Object-disclosure measurement gap, found and fixed.** The first new flow implementation returned only a generic synthetic marker for reads. A ledger increment could therefore establish an attempted operation, but not another object's value reaching the caller. The corrected implementation returns a fixed per-object synthetic value. Independent tests observe the beta value in an unsafe alpha request, no value/effect in either protected route, and the expected alpha value in a valid read.

## AI comparison safeguards

The registered older corpus places sequential case IDs into truth-group blocks. Those IDs are nominally opaque, but a fresh trial should use randomized opaque IDs and a frozen order/manifest before its first model call. Do not tune prompts or cases after seeing the first result and still call the same sample held out. Register modifications and disclose reuse.

The existing evaluator compares incident assessments. It does not independently score whether a proposed action is necessary, whether requested reads add information, analyst time saved, or actual containment/recovery. Higher assessment accuracy therefore supports only the declared synthetic triage comparison. A schema-valid, known-evidence proposal can still be semantically wrong. Safety validation remains necessary and is not an efficacy oracle.

An unavailable or malformed provider falls back to deterministic investigation for operational continuity. The independent tests require that this fallback never count as a successful AI decision. A configured but exhausted global reservation must make zero provider requests; an absent provider must publish no simulated AI metric. Provider-reported model identity is recorded as unverified, and transport tests explicitly identify their fixed completion as a test double.

For a fair fresh challenge, retain benign lookalikes, contradictory/missing observations, an authorized-output inference counterexample and observably identical traces with different hidden controller histories. The last pair cannot honestly be distinguished from the provided observations: more confident answers are not extra information. Report unresolved history as unknown. Neither arm receives private labels, raw source, credentials, arbitrary URLs or execution authority.

## Independent results

The first three tests inspect the actual loopback HTTP request sent by the production gateway against an explicitly synthetic completion fixture. They verify that evaluator truth/group/description and a credential canary stay out of the payload, that accepted events and action scope are retained, and that degraded/unconfigured/budget-blocked inference earns no AI credit. These checks validate the comparison boundary; they are not a real model run.

The independent file passed **10 Python tests** in **10.701 seconds** in the local Windows environment. One Python test copies the exact non-test Go flow source into an isolated temporary module and compiles/runs **three separately authored Go tests**. These are nested checks, not thirteen distinct incident samples. The installed Go toolchain is required; absence is a visible skip.

The Go tests independently confirm object-value disclosure/denial, revocation at both declared paths and continued access for an unrelated principal. Twenty-four separate approved grants racing the same transaction key produce one ledger row and one charged unit. A changed same-key payload returns conflict; a fresh approved key charges its legitimate two units. A grant at its exact expiry denies further effect. The unsafe receiver gets the fixed synthetic payload; the protected allowed receiver gets its approved payload; forbidden recipient and redirect cases yield zero requests at the forbidden receiver. Replaying the consumed redirect grant cannot retry delivery.

Five publication counterexamples use an independent HTTP client against the owned fixture. Cached private script/map bytes remain available under identity and gzip after origin promotion alone. Explicit retirement stops future delivery through the controlled origin and edge while preserving all six required root/index/script GET representations. Saved bytes remain disclosed. Two concurrent promotion approvals produce one generation transition. A source modification after final validated read cannot replace the installed immutable approved snapshot. Exact expiry, changed candidate and public HTTP approval attempts cannot change the active generation. A delayed pre-purge cache fill cannot resurrect a retired map or stale script.

The reviewer accepts only these selected application and publication invariants. No production authority, restart durability for the Go/publication components, arbitrary SSRF resistance, general credential protection, historical disclosure reversal or real AI advantage follows. The actual CLIProxyAPI run, if available, must publish its own route/corpus manifest and per-case outcomes separately from these tests. Historical failed measurements above retain their original state so the reason for each correction remains reviewable.

## Evaluator and gateway integration follow-up

The separate [aggregate/evaluator tests](../../tests/test_next_wave_integration.py) reproduce three additional provenance/data-loss defects: benchmark output could replace its input corpus, the direct comparator accepted a corpus changed during inference, and a separate manifest read could hash bytes different from those already loaded for scoring. The corrected implementation guards output before inference, hashes the exact loaded text and rejects source drift. A forced investigation exception also confirms the SQLite store closes before temporary-directory cleanup, preserving the original error. Safe progress callbacks expose only arm/index/count/status rather than requiring inspection of an open database. Rejected and degraded rows receive no proposal or required-hypothesis credit.

An actual CLIProxyAPI trial revealed another integration defect missed by the earlier `CatalogDouble`: the real gateway expected every catalog result to contain `events`, but the Go `access_patterns` result contains typed `candidates` and `coverage`. The corrected adapter validates the distinct shape before projecting known candidate codes/evidence references and fixed coverage/limitation enums. Labels, observed counts and arbitrary source fields are excluded from this projection. The [new real-HTTP catalog tests](../../tests/test_gateway_catalog.py) exercise the production gateway with a scripted completion peer requesting a real Go catalog read; the second call receives the validated result and completes. Twelve malformed variants fail before any HTTP request. Ordinary catalog ID projection remains tested separately, and secret-shaped error codes cannot enter results, health or persisted episode records.

The following trial exposed repeated read requests until the hard round limit. Each inference request is stateless, so hiding the number of remaining reads creates a protocol gap. The reviewer accepts runtime-derived `readRoundsRemaining` of 2, 1 and 0 plus generic finalization/uncertainty instructions as a protocol correction: it supplies no extra observation, truth label, scenario-specific answer or execution authority. The gateway validates the exact bounded integer and the supervisor owns it. A budget-aware scripted peer completes; a peer that continues asking at zero still degrades after exactly three calls. The runtime does not clear those requests silently or credit deterministic fallback as AI success.

All **seven catalog tests passed** locally in 5.417 seconds. These are transport/protocol regressions with explicit completion doubles, not model-quality measurements. Earlier actual model runs must remain disclosed separately, including integration failures and budget/degradation costs; only persisted actual-provider artifacts can support a comparison result. `requiredHypothesisMatches` measures required-code presence, not hypothesis precision or independently adjudicated semantic correctness. Protocol corrections and subsequent public-regression runs cannot be represented as a pristine held-out trial.

## Final disposition after actual-provider artifact review

The reviewer independently recomputed the [final record](../lab/evidence/next-wave.json)'s eight source hashes, [corpus hash](../lab/evidence/next-wave-corpus.json), effect-manifest commitment and all three [trial artifact hashes](../lab/evidence/next-wave-trials.json). They agree. Each completed trial uses the same registered corpus. Row totals agree with reported calls, conservative reserved tokens, valid/degraded cases, acceptable assessments, proposal checks and required-code presence. The final reported model identifier is `gpt-6.1-sol`; this remains a proxy-reported identifier, without independent upstream attestation. The interrupted older 48-case attempt and its unknown usage are disclosed rather than scored.

The final v3 actual-provider run supplies **16 validated decisions**, with **16/16 acceptable coarse assessments for both AI and frozen baseline**. Eight unknown cases remain unknown in both arms. AI has 16 acceptable next-step checks versus the baseline's 12, and 14 required-code matches versus 13. The four proposal differences are the three failed-recovery observations and one source-loss ablation: recommending human review for those predicates is a plausible small deterministic lookup improvement. AI also fails to include the registered `control_gap` code in that case. The presence metric does not establish precision or correct reasoning.

The model requires **41 calls**, **171,631 conservative reserved visible tokens** and **318.469 seconds**, compared with **4.078 seconds** for the baseline arm. These are selected run measurements, not billing or field-performance estimates. Earlier completed runs retain their thirteen degraded cases each; adapter/protocol repair changes the experiment version rather than erasing those failures.

**Accepted:** working actual-provider integration with bounded reads, visible failures, a reproducible public comparison and the selected independently observed fixture effects. **Not established:** incremental operational AI value, better prevention/containment/recovery, analyst-time saving, representative attack accuracy or production acceptance. The current [results disposition](../lab/NEXT_WAVE_RESULTS.md) correctly keeps that distinction. A stronger frozen rules-plus-lookup baseline and new ambiguous incidents are required before claiming that the remaining proposal/code differences justify the model's latency and usage.
